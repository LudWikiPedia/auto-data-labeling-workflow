## 怎么测

0. **先知道会发生什么**（2026-11-05 实测官方 demo 运行状态）：两个 Space 都在 `RUNNING`，但硬件档位是 `zero-a10g`——**这是 Hugging Face 的免费 CPU 档，没有显卡**。所以：
   - 单张图等 30 秒到几分钟是正常的，**不是卡死**，别中途关掉重开（重开会重新排队）
   - 4B 在免费 CPU 上很可能超时或干脆报错。碰到这种情况按「本机测不了 4B」记录，**不要**因此判模型不行——那是硬件的锅，不是模型的锅
   - 建议顺序：先 2B 跑完 20 张，再挑 5 张最难的试 4B
   - 免费档闲置 48 小时会回收，隔天再点可能要等它冷启动
1. 打开官方 demo（不用注册）：
   - 4B：https://huggingface.co/spaces/hugging-apps/wevisone-vl-4b
   - 2B：https://huggingface.co/spaces/hugging-apps/wevisone-vl-2b
2. 从我们真实要标的数据里抽 20 张，**不要挑好看的**，按真实分布抽。目标类别已定为**车辆 / 行人 / 宠物**，配额：

   | 类别 | 张数 | 其中必须是麻烦情况 |
   |---|---|---|
   | 车辆 | 7 | ≥2（夜间、远处小客车、车辆密集排队、车被遮挡） |
   | 行人 | 7 | ≥2（背影/侧脸、人群重叠、只露一半、撑伞戴口罩） |
   | 宠物 | 6 | ≥2（长毛、深色宠物在暗背景、多只挤一起、被家具挡） |

3. 每张图跑 3 组提问，**第 3 组是专门测「提示词措辞敏感」这条限制的**：
   - `detection` 给类别名：车辆用 `car`、行人用 `person`、宠物用 `dog` 或 `cat`
   - `referring` 给一句描述，例如「穿红色上衣的人」「停在路边的白色轿车」
   - **宠物这一类额外再问一次 `pet`**（而不是 `dog`/`cat`）。官方模型卡明写 `Fine alpha boundaries remain sensitive to ... prompt phrasing`（提示词换个说法结果就变），所以「宠物」这个词到底认不认得，必须实测，不能猜。两组结果不一样，就把两个措辞都记下来。
4. **无目标提问 3 组（最关键的一步）**：从上面 20 张里挑 3 张，各问一个图里确实没有的东西（比如问「自行车」而图里只有行人）。看它会不会答 `None`。这一步直接决定能不能拿它当自动闸门——记在第 21–23 行，**不是新图，是换提问方式**。
5. 4B 只跑 **5 张最难的**（免费 CPU 档跑不动 20 张，见第 0 步）。这 5 张从三类里各挑，专挑第 2 步标的「麻烦情况」。

## 打分口径（先定死再开始，不要边测边改）

需求写的是「**大幅减少人工画框的工作量**」，所以主指标不是准不准，是**人还要花多少时间改**。准确率只是它的中间量。

框和掩码**分开打分**——需求两个都要，但这两件事难度差很远，混成一个分会看不出问题出在哪。

| 分值 | 意思 |
|---|---|
| 2 | 可直接当标注用，人只需点确认 |
| 1 | 目标找对了，但位置或轮廓要人改，比从零画省力 |
| 0 | 目标找错、漏了、框了个不存在的东西，或者掩码根本不能用 |

## 判完成的线

- 2B 框分平均 ≥ 1.5、掩码分平均 ≥ 1.0，且无目标提问至少 2/3 答对 → 值得往下走，开始算租卡成本
- 框分够但掩码分 < 1.0 → **只用它出框，掩码这条路换 SAM 或人工**，别整体砍掉
- 框分 1.0–1.5 → 只能当辅助，不能当预标注主力，流程要重新想
- 框分 < 1.0 或无目标提问全错 → 这个模型路线放弃
- 「宠物」用 `dog/cat` 和用 `pet` 结果不一样 → 单独列出来登记成风险，并把选定的措辞写进流程配置
- **省人力这条要单独算**：拿 20 张的「人改这张花了」求平均，跟纯手工画一张的时间比。比值不到 2 倍，就谈不上「大幅减少」，得重新评估值不值得做

上面的及格线是拍脑袋定的，没有依据。跑之前五个人一起改这三个数（1.5 / 1.0 / 2 倍），比跑完再吵便宜。
